# 前端适配与阶段文档模板

## 《前端技术适配声明》

编码前输出，保持短、明确、可确认。

```markdown
# 前端技术适配声明

## 1. 项目判断
- 产品类型与核心任务：
- 主要用户：
- 主要终端：桌面 Web / 移动 Web / 其他
- 新项目或已有项目：
- 本阶段用户可完成的业务目标：

## 2. 输入资料
- PRD：已读取 / 缺失
- 后端手册或技术适配声明：已读取 / 缺失
- 接口契约：完整 / 草案 / 缺失
- 设计稿或视觉参考：有 / 无
- 现有代码与项目规则：有 / 无

## 3. 技术选择
- 框架、运行时与实际版本：
- 样式、设计变量和组件策略：
- 数据请求与四类状态归属：
- 流式、轮询或实时通信：
- 表单与运行时校验：
- 测试和浏览器验收：
- 目标部署环境：

## 4. Agent 状态
- 后端状态 → 前端统一状态映射：
- waiting_user 的交互与持久化：
- 提交幂等、取消和重试：
- 断线和刷新恢复：
- 任务 ID 与恢复入口：

## 5. 页面、设计与产物
- 核心页面与路由：
- 第一条真实业务闭环：
- 设计来源与代表页：
- 产物类型与预览方式：
- 响应式验收宽度：

## 6. 偏离默认方案
- 偏离项：替代方案；原因；影响；回退或重新评估条件

## 7. 强制底线检查
- 前端秘密与公开配置：通过 / 待处理
- 后端事实来源与权限：通过 / 待处理
- 状态、错误和恢复：通过 / 待处理
- 移动端与无障碍：计划
- 自动检查、真实后端和浏览器验收：计划

## 8. 待确认事项
- 只列会明显影响方向、核心视觉、范围、成本、安全或工期的问题；没有写“无”

## 9. 下一步
- 产品经理当前只需要：
- 确认后本阶段将交付：
```

若全部沿用现有合理方案且没有关键待确认项，可报告后继续。不能用大量低价值问题阻塞开发。

## 《分阶段前端开发文档》

```markdown
# 第 N 阶段前端开发文档｜{阶段名称}

## 1. 本阶段目标
- 用一句产品语言描述用户完成什么：
- 入口条件：

## 2. 范围
### 本阶段包含
- 页面与路由：
- 组件：
- 接口：
- 任务状态：
- 产物：
- 设计与响应式：

### 本阶段不包含
- 明确排除项：

## 3. 用户流程
1. 用户进入：
2. 用户输入或操作：
3. 系统提交与执行：
4. 等待确认或错误恢复：
5. 用户得到真实结果：
6. 刷新或重新进入后的恢复：

## 4. 页面状态矩阵
| 页面/模块 | 初始 | 加载 | 空 | 提交 | 队列 | 运行/流式 | 等待确认 | 部分成功 | 成功 | 失败 | 断线/恢复 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | | | |

## 5. 接口契约
- 接口：
- 请求与运行时校验：
- 成功返回：
- 错误与用户恢复方式：
- 鉴权与权限：
- 幂等、超时与重试：
- 状态映射和未知值兜底：
- Mock 与真实接口切换：

## 6. 实现方案
- 路由与 Server/Client 边界：
- 组件结构和复用边界：
- URL、服务端、页面临时和用户偏好状态：
- 流式、轮询或实时多媒体：
- 产物预览与下载：
- 设计变量、字体和资产：
- 响应式与无障碍：
- 安全、隐私和性能：

## 7. 测试与验收
- 单元与组件测试：
- 集成与 E2E：
- lint、typecheck、test、build 命令：
- 真实后端闭环：
- 浏览器、Console、Network：
- 390 / 768 / 1280 / 1440 或 PRD 指定宽度：
- 真实手机与权限能力（如适用）：

## 8. 风险与回退
- 风险与影响：
- 降级方案：
- 回退方式：
- 未冻结业务规则及可配置位置：

## 9. 交付结果
- 修改文件：
- 自动检查：
- 浏览器与真机结果：
- 未完成或待验：
- 已知问题：
- 产品经理下一步只需：
```

## 写作检查

- 阶段按真实用户闭环而不是文件或页面数量拆分。
- “本阶段不包含”能防止默认实现整份 PRD。
- 页面状态矩阵覆盖异常和恢复，不只成功态。
- 接口字段、状态、错误和产物能追溯到后端契约。
- 验收项写成非技术产品经理能照着操作并观察的步骤。
- 未冻结规则用“模拟/临时”显式标记并可配置，不当作正式完成。
