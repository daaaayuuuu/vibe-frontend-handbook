# Agent 任务、流式与恢复交互

## 统一任务状态

后端命名可以不同，但前端适配层必须映射成稳定含义：

| 统一状态 | 用户看到什么 | 前端职责 |
| --- | --- | --- |
| `idle` | 尚未开始 | 显示输入、限制和执行条件 |
| `submitting` | 正在提交 | 防重复，允许取消当前请求 |
| `queued` | 已受理、等待执行 | 不伪装成正在生成 |
| `running` | 正在执行 | 显示真实阶段、进度或活动提示 |
| `streaming` | 持续输出 | 增量且稳定展示 |
| `waiting_user` | 等待确认或补充 | 说明原因、选项和影响 |
| `succeeded` | 已完成 | 展示产物与下一步 |
| `partially_succeeded` | 部分完成 | 清楚区分成功与失败项 |
| `failed` | 执行失败 | 说明可恢复方式并保留输入 |
| `cancelled` | 已取消 | 保留已有信息并允许重启 |
| `disconnected` | 连接中断 | 告知任务未必停止并尝试恢复 |
| `stale` | 状态可能过期 | 主动获取后端真实状态 |

未知状态记录并显示安全兜底，不能默认为成功或失败。每个状态回答：现在发生什么、用户要做什么、接下来会怎样。

区分：

- `loading`：请求未返回；
- `empty`：请求成功且确实无数据；
- `failed`：请求失败；
- `permission_denied`：无权限；
- `not_found`：对象不存在或已删除。

数据尚未返回时禁止先显示“暂无任务”或“暂无模板”。

## 通信方案选择

| 场景 | 默认 |
| --- | --- |
| 服务端单向持续推送文本或进度 | SSE 或 Fetch Streaming |
| 双向高频通信 | WebSocket |
| 后端只支持状态查询 | 有节制轮询 |
| 普通短请求 | HTTP |

不为“实时感”强行使用 WebSocket。

### SSE 与 Fetch Streaming

- `EventSource` 适合 GET，但不方便加自定义请求头；需要 POST、请求体或特殊鉴权时优先 Fetch Streaming。
- Cookie 鉴权优先走同源接口。代理可能缓存流，必须在真实部署链路确认分段到达。
- 页面卸载、任务切换和取消时关闭连接。
- 断线后先按任务 ID 查询真实状态，再决定重连，不能重复创建任务。
- 重连后对事件或内容去重。

### 轮询

- 明确间隔、退避和最大错误频率；页面不可见时降频或暂停。
- 完成、失败或取消后立即停止。
- 同一任务只有一处请求协调，不让每个组件重复轮询。
- 接口失败时不无限高频重试。

### 增量展示

- 批量或节流更新，避免每个字符触发复杂重渲染。
- 只有用户仍在底部时自动滚动；查看历史时不抢走位置。
- 最终结果、过程信息和内部调试分层；不泄露思考过程或敏感信息。
- 断线恢复按稳定事件 ID、序号或后端快照去重。

## 用户确认是一等状态

`waiting_user` 必须展示：已完成什么、为何确认、选项与影响、推荐项、是否可撤销、放弃或返回方式。按钮使用业务动作，例如“采用这版分镜并生成视频”，不用含糊的“确定”。

关键确认由后端持久化。刷新、重新登录或换终端后能通过任务 ID 恢复，不能只依赖弹窗本地状态。

## 防重复、重试与取消

- 点击提交后立刻进入明确的 submitting 状态并禁用重复触发。
- 后端使用幂等键；网络超时时先查询原任务是否创建，再决定重试。
- 高成本模型任务不因连点或盲目重试重复扣费。
- “取消浏览器请求”只停止等待；“取消后端任务”必须有真实后端能力。
- 后端不能取消时写“停止等待”或“离开页面”，不能误导为任务已取消。
- 失败后保留用户输入和已生成产物，明确重试会重做什么、是否再次计费。

## 刷新与断线恢复

1. 从 URL 或任务列表得到任务 ID；
2. 查询后端真实状态；
3. 恢复中间结果、确认点和产物；
4. 任务仍运行且协议允许时再恢复流；
5. 不重复创建任务。

动画结束、计时完成或连接断开都不能证明任务完成，必须以后端状态与产物为准。

## 实时语音与多媒体

实时语音链路通常是：麦克风录音 → 上传 → ASR → Agent 回复 → TTS → 音频流回传 → 播放。

### 前端最低处理

1. 麦克风只在 HTTPS 或 localhost 可用。拒绝授权时给明确引导，未授权不开始录音。
2. 文本 `chunk` 与音频 `audio` 可能并行。用 Web Audio API 按时间轴排队，避免重叠；结束或切换会话时清空队列。
3. 运行时探测 `MediaRecorder` MIME。Chrome 常见 `webm/opus`，iOS/Safari 常见 `mp4/aac`；上传时把实际格式交给后端。
4. MVP 优先回合制录音与发送；全双工和 barge-in 作为明确的后续能力。
5. 受鉴权保护的音频不能直接假设 `<audio src>` 可用；可带鉴权 `fetch` 为 Blob 和 Object URL，使用后释放。

### 真实设备验收

在真实手机，包含 iPhone，完成录音 → 上传/转写 → 回复 → 播报 → 会后整段或逐句回放。检查授权拒绝、切后台、锁屏、断网、切换会话和已完成轮次恢复。会中不泄露答案、评分或内部调试信息，除非 PRD 明确要求。
